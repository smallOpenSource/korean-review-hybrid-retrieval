# 장애 조치 및 개선 보고서

## 1. 현상 (Phenomenon)
- **민원 현황판 데이터 누락**: '유형', '부서' 컬럼에 `None`으로 표시되는 데이터 다수 존재.
- **상세 분석 데이터 부재**: 회사 상세 및 부서별 분석 페이지에서 "데이터가 없습니다" 또는 빈 차트 표시.
- **UI 불완전성**: 주요 페이지(대시보드, 민원 현황판 등)에 "(개선중)"이라는 텍스트가 하드코딩되어 노출됨.
- **데이터 불일치**: 대시보드 총 리뷰 수(65k)와 세부 데이터 간 괴리 존재.

## 2. 원인 (Cause)
1.  **데이터 분석 미비**:
    - OpenSearch로 데이터 동기화(`sync_to_opensearch`)는 진행 중이나, 리뷰에 대한 AI 분석(유형 분류, 부서 배정 등)이 완료되지 않은 상태.
    - DB의 `complaint` 필드(JSON)가 비어있거나 `null`인 상태로 동기화됨.
2.  **UI 렌더링 로직 미흡**:
    - `complaints.py`에서 DB 값이 `None`일 경우, 이를 적절한 기본값(예: "미분류", "분석중")으로 변환하지 않고 그대로 템플릿에 전달.
    - Jinja2 템플릿이 Python의 `None` 객체를 문자열 "None"으로 렌더링.
3.  **하드코딩된 UI 요소**:
    - HTML 템플릿 파일 내에 "(개선중)" 텍스트가 직접 작성되어 있음.

## 3. 문제점 (Problem)
- **사용자 신뢰 하락**: "안정화되었다"는 보고와 달리, 실제 화면에서는 데이터가 깨져 보이거나 완성되지 않은 모습을 보임.
- **가독성 저하**: `None`과 같은 시스템 용어가 그대로 노출되어 전문성 결여.
- **기능 오작동**: 분석되지 않은 데이터로 인해 필터링 및 통계가 정확하지 않음.

## 4. 해결방안 (Solution)
1.  **UI 결함 수정 (즉시 조치)**:
    - `complaints.py` 및 템플릿에서 `None` 값을 "분석 대기중" 또는 "-"로 치환하여 표시.
    - 하드코딩된 "(개선중)" 텍스트 제거.
2.  **데이터 표현 개선**:
    - 분석 데이터가 없는 경우, 사용자에게 "데이터 분석 중입니다"와 같은 명확한 상태 메시지 제공.
3.  **분석 파이프라인 점검 (후속 조치)**:
    - 스케줄러 코드를 점검하여 분석 작업(`analyze_reviews`)이 정상적으로 스케줄링되어 있는지 확인 (인프라 조작 없이 코드 레벨 확인).

## 5. 조치계획 (Action Plan)

### Cycle 1: UI 데이터 표현 정상화 (Fix "None")
- **대상**: `app/views/complaints.py`, `app/templates/pages/complaint_board.html`
- **내용**:
    - `None` 데이터를 "미분류" 또는 "분석중"으로 매핑하는 로직 추가.
    - `severity`, `urgency` 등의 기본값 처리 강화.
- **검증**: 민원 현황판에서 `None` 텍스트가 사라지고 적절한 상태 메시지가 표시되는지 확인.

### Cycle 2: UI 잔여 태그 제거 (Remove "개선중")
- **대상**: `app/templates/pages/*.html`
- **내용**: 모든 페이지에서 "(개선중)" 텍스트 삭제.
- **검증**: 페이지 로딩 후 해당 텍스트 미노출 확인.

### Cycle 3: 차트 및 상세 페이지 예외 처리
- **대상**: `app/views/dashboard.py`, `app/templates/pages/company_detail.html`
- **내용**: 데이터가 부족한 경우 빈 차트 대신 안내 메시지 또는 스켈레톤 UI 표시 로직 보완.
- **검증**: 데이터가 없는 회사/부서 조회 시 깨짐 없이 안내 문구 표시 확인.
